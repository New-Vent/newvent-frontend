# src/event-css — 이벤트 페이지 스타일 원본

여기 파일들을 **경로 순서대로 이어 붙여** `public/assets/event.css` 한 파일을 만든다.
게시 페이지 · 미리보기 iframe · 템플릿이 전부 `/assets/event.css` 를 링크한다.

- `npm run dev` · `npm run build` 가 자동으로 다시 만든다 (vite.config.js 의 `eventCss` 플러그인)
- 손으로 만들기: `npm run css`
- 원본과 결과가 같은지 확인: `npm run css:check` (CI · 커밋 전)
- **`public/assets/event.css` 는 직접 고치지 않는다** — 다음 빌드에서 덮인다

## 백엔드 레지스트리와 짝

| CSS | 백엔드 | 추가할 때 |
|---|---|---|
| `60-variants/NN-블록.css` · `70-components/06-compare.css` 의 `.v-*` | `registry/Variant.java` | 양쪽에 같은 이름 |
| `90-palettes/*.css` 의 `.palette-*` | `registry/Palette.java` | 변수 11개(primary · hover · light · glow · gradient-hero · gradient-cta · accent-tag · bg · surface · surface-subtle · border), 어두우면 text-* 3개 + `99-dark-fixes` |
| `70-components/02-inline.css` 의 `.t-*` | `registry/Inline.java` | |
| `50-blocks/NN-블록.css` | `registry/Block.java` | 새 블록의 기본 모양 (= 기본 변형의 모양) |

저장소가 달라 이름이 어긋나도 테스트가 못 잡는다. 이름을 바꾸면 양쪽을 같이 고친다.
레지스트리에만 있고 CSS 가 없는 이름은 **기본 모양과 같은 기본 변형**이다 (예: `v-stats-grid`, `palette-base`).

디자인 출처: Bootstrap(jumbotron · alert · card · pricing · table · accordion-flush) · HyperUI · Preline · Flowbite · DaisyUI.
Tailwind 유틸리티를 그대로 쓰지 않고 이름 붙은 class 로 옮겼다 — 이벤트 페이지에는 Tailwind 가 없고, 모델이 고르는 이름은 검증 가능해야 한다.

### 방침: 템플릿 전용 포인트색 토큰

1. 바꾸는 것은 **포인트색뿐**이다. 중성색과 상태색(성공 · 경고 · 비활성 · 완료)은 토큰화하지 않는다. 템플릿이 사라지거나 의미가 깨진다. `08-interactive.css` 에도 버튼 · 게이지 같은 **포인트색**이 있다 — 그 파일 전체를 상태색으로 보지 말고, 상태색(완료 초록 · 다운로드 회색 · 마일스톤 달성 초록)만 남기고 치환한다.
2. **기본 모양은 그대로여야 한다.** 그래서 hex 를 `var(--ev-primary)` 로 바꾸지 않고, 테마 블록에 **지금 값 그대로** 템플릿 전용 토큰(`--tpl-` 접두사)을 정의해 그것을 쓴다.

   ```css
   .theme-vip { --tpl-accent: #cca43b; }
   .theme-vip .vp-example { color: var(--tpl-accent); }
   ```

   투명도가 있는 포인트색(`rgba(220, 38, 38, 0.12)`)은 토큰 하나에서 투명도만 달리하도록
   `color-mix(in srgb, var(--tpl-accent) 12%, transparent)` 로 바꾼다.

3. 팔레트가 붙을 때만 `--tpl-*` 가 팔레트의 포인트색을 따르게 한다. 이 연결 규칙은 `90-palettes/95-template-accent.css` 한 곳에 둔다 (아래 「팔레트 연결」). 치환 단계에서는 팔레트 연결 없이 화면이 그대로인지만 확인하고, 연결은 치환이 모두 끝난 뒤에 넣었다.
4. 어두운 템플릿(sale)은 팔레트의 `--ev-primary` 를 그대로 쓸 수 없다. 팔레트의 포인트색은 밝은 바탕용으로 고른 진한 색이라 어두운 카드 위에서 대비가 모자란다 (18종 중 15종이 4.5 미만). 어두운 바탕용 변종이 따로 필요하다. sale 만의 문제가 아니다 — 밝은 템플릿에도 어두운 영역이 있다 (예: sports 의 히어로 · 스코어보드는 어두운 남색 바탕 위에 밝은 빨강 글자).
5. 치환할 때마다 **팔레트 없는 상태에서 계산된 스타일 차이가 0** 인지 확인한다 (아래 「규칙」의 분리 때와 같은 기준). 치환 전후의 CSS 로 같은 템플릿을 그려 요소마다 색 관련 계산값을 **숫자(RGBA)로 풀어서** 비교한다 — `color-mix` 는 계산값 문자열이 `rgba()` 와 다르게 찍히기 때문이다. `:hover` · `.active` 상태와 팔레트 몇 가지도 함께 본다. 템플릿 HTML 이 쓰지 않는 규칙(예: `.hl-gift-featured`)은 CSS 선택자에서 가짜 요소를 만들어 같은 비교를 한다. 정의한 토큰을 한 단계씩 바꿔 보고 화면이 실제로 달라지는지도 확인한다 (정의만 있고 안 쓰이는 토큰이 없도록).

`40-templates/0N-*.css` 와 `08-interactive.css` 를 모두 본다. 토큰은 24개다.

| 템플릿 | 토큰 | 치환한 곳 (`0N` / `08`) | 남긴 곳 |

토큰은 `20-themes/01-template-themes.css` 의 해당 테마 블록에 정의한다. 값은 치환 전 hex 그대로다.

이름은 색의 성격을 따른다 — `accent`(기본), `-deep`(진한 변종), `-bright`(어두운 바탕 위의 밝은 변종), `-soft` · `-light`(연한 변종), `-hover`(마우스를 올렸을 때), `-ink`(글자용 짙은 색). 장식과 특정 부품은 쓰임새로 부른다 — `ribbon` · `step` · `warm`(복주머니 카드의 주황) · `gold`(쿠폰 버튼의 금색).

**연한 색조 바탕**(`#fffbeb`, `#eff6ff` → `#dbeafe` 등)은 "배경은 건드리지 않는다"는 원칙에 따라 남겼다. holiday 의 선물 카드(`.hl-gift-featured`)와 launch 의 대표 상품 카드(`.lc-prize-featured`)는 출하 템플릿 HTML(`holiday_gift.html` · `pre_registration.html`)이 쓰지 않는 규칙이라 지금 화면에는 나오지 않는다. 쓰기 시작하면 그때 바탕을 팔레트에 맞출지 정한다.

**일러스트는 따라가지 않는다.** 복주머니의 몸통(빨강 · 금 · 파랑)은 상품을 구분하는 색이고, 그 위의 `福` · 목도 몸통 색에 맞춰 고정이다. 이 위의 요소를 팔레트 토큰에 묶으면 대비가 무너진다 (처음에 묶었다가 되돌렸다).

### 팔레트 연결

`90-palettes/95-template-accent.css` 가 팔레트의 값을 `--tpl-*` 에 연결한다. 규칙은 전부 `[class*="palette-"]` 가 붙은 루트에만 걸리므로, **팔레트가 없으면 템플릿은 `20-themes` 의 값 그대로다.**

팔레트는 포인트색을 `--ev-primary` 하나로 주는데, 템플릿은 그 색을 쓰임새가 다른 곳에 쓴다. 한 값으로는 다 못 맞춰서 역할로 나눠 연결한다.

| 쓰임새 | 쓰는 값 | 이유 |
| --- | --- | --- |
| 밝은 바탕 위의 글자 · 흰 글자가 얹히는 채움 | `--ev-primary-hover` | 팔레트가 이미 진하게 골라 둔 값이다. 밝은 팔레트 16종 모두 흰색 대비가 5.7 이상. 기본색은 summer 4.10 · pastel 4.23 으로 모자란다 |
| 어두운 바탕 위의 글자 · 선 | `--ev-primary-on-dark` | 색상 · 채도는 두고 밝기만 0.74 아래로 못 내려가게 한다. 어두운 바탕 5곳(`#121215` · `#1e293b` · `#292524` · `#3d1627` · `#172554`) 위에서 18종 모두 4.95 이상. 이미 밝은 night · esports 는 그대로 |
| 그보다 연한 금색 계열 | `--ev-primary-on-dark-soft` | on-dark 에 흰색을 55% 섞는다 |
| 진한 끝 (버튼 그라데이션) | `--ev-primary-deep` | hover 에 검정을 22% 섞는다 |
| 테두리 · 빛번짐 같은 장식 | `--ev-primary` | |

파생 값 셋은 팔레트마다 적지 않고 95 에서 한 번에 만든다. 팔레트를 추가해도 따로 할 일이 없다.

| 템플릿 | 연결 |
| --- | --- |
| sports · launch | `accent` ← hover · `-deep` ← deep · `-bright` ← on-dark. launch 는 `-light`(진행 막대 · 포커스 테두리) ← primary. launch 의 `-ink`(연한 바탕 위 짙은 글자)는 **연결하지 않는다** — 쓰는 카드의 바탕이 안 바뀐다 |
| holiday | `accent` ← primary · `-deep` ← hover · `-soft` `-light` ← on-dark-soft · `ribbon` ← hover · `step` ← deep · `warm` ← hover · `warm-deep` ← deep |
| vip | `accent` ← on-dark · `-light` ← on-dark-soft · `-deep` ← hover · `gold` ← on-dark · `gold-deep` ← hover |
| sale | `accent` ← on-dark · `-hover` ← on-dark 에 검정 15% · `-soft` ← on-dark-soft |

토큰만으로 안 풀리는 곳은 규칙을 따로 건다.

- **sale 안의 공유 블록**(소제목 · 버튼)도 어두운 바탕 위에 있다. 같은 루트에서는 `--ev-primary` 를 자기 값으로 다시 정의할 수 없어서(순환) 바로 아래 자식 요소에 건다.
- **holiday 히어로**의 공유 `.highlight` 는 `--ev-accent-tag` 를 쓰는데, 팔레트의 태그색은 밝은 바탕용이다 (valentine 의 `#7f1d1d` 는 와인색 히어로 위에서 대비 1.56). 히어로 안에서만 on-dark 로 바꾼다.
- **밝은 템플릿 4종의 공유 CTA**는 hover → deep 의 진한 그라데이션과 흰 글자를 쓴다 (밝은 팔레트 한정). 팔레트 자신의 CTA 그라데이션은 밝은 쪽 끝 때문에 18종 중 9종이 흰 글자 · 어두운 글자 어느 쪽으로도 4.5 에 못 미친다.
- **밝은 템플릿 4종의 공유 블록**(소제목 · 혜택 값 · 태그)은 `--ev-primary` 를 hover 로 바꾼다 (밝은 팔레트 한정, 바로 아래 자식에 건다). summer · pastel 의 기본색이 흰 바탕 글자 기준에 못 미쳐서다. 템플릿 자신의 어두운 영역은 `--tpl-*` 를 쓰므로 영향이 없다.
- **vip 쿠폰 카드**는 바탕이 밝은색(`#fafaf9`)으로 고정이다. 안의 `.benefit-value` 는 deep 으로.
- **어두운 팔레트(night · esports)** 는 `99-dark-fixes.css` 에서 — 노랑 · 초록 위에 얹힌 흰 글자(버튼 · 번호 배지)를 어둡게, 흰색으로 고정된 카드(launch 타임라인 · 게이지, holiday 복주머니) 위의 포인트색 글자를 deep 으로, 연한 파랑 바탕이 고정인 마일스톤 배지를 짙은 남색으로.

**브라우저**: on-dark 는 `oklch(from …)`(상대 색 문법)을 쓴다. 못 읽는 브라우저는 `@supports` 밖의 대체값(흰색 55% 섞기)을 쓰는데, 같은 대비 기준을 통과한다 (최저 5.0). 이 경로는 Chrome 에서 `@supports` 블록을 지운 CSS 로만 확인했고 실제 구형 브라우저에서는 확인하지 못했다.

**새 토큰을 만들면** 95 에 연결을 같이 추가한다. 빠뜨리면 그 색만 팔레트를 안 따라가고, 아래 테스트가 잡는다.

- main 에서 미달이던 것이 통과로 바뀐 곳: 161건 (sale 의 소제목 · 타이머, holiday 의 CTA, vip 의 쿠폰 …)

### 템플릿 페이지에서 되는 수정 / 안 되는 수정

AI 수정에서 색 · 모양을 바꾸는 길은 셋이다 — 팔레트, 테마, 모양 변형(`v-*`). 템플릿 페이지에서의 상태:

| 수정 | 템플릿 페이지에서 | 근거 |
| --- | --- | --- |
| **전체 색감 (팔레트 18종)** | **된다.** 포인트색(버튼 · 강조 글자 · 배지 · 테두리 · 게이지 · 진행 막대)이 바뀐다. hero 를 고칠 때 붙고 서버가 루트로 옮긴다 | `PromptBuilder.edit` 은 템플릿 블록이어도 팔레트를 안내한다. 연결은 이 문서 「팔레트 연결」 |
| 〃 바탕 · 카드 · 글자 같은 중성색 | **안 바뀐다 (의도).** sale 은 검은 바탕, 나머지는 밝은 바탕을 유지한다 | `97-template-neutrals.css` |
| 〃 어두운 팔레트(night · esports) | 된다. 밝은 템플릿의 흰 카드는 그대로 두고 글자가 읽히게만 맞춘다 | `99-dark-fixes.css` |
| 〃 복주머니 일러스트 · 완료 · 다운로드 · 달성 상태색 · 창 장식 점 | 안 바뀐다 | 색이 뜻을 가진다 |
| 테마 (basic · bloom · aurora) | **안 된다.** 템플릿 루트에는 `theme-sports` 같은 다른 벌이 붙어 있어 갈아끼우면 디자인이 깨진다. 프롬프트도 안내하지 않는다 | `PromptBuilder.edit` 의 `themes = palette && !templateBlock` |
| 모양 변형 (`v-*`) | **안 된다.** 변형 규칙은 `[data-block]:not(.ev-block)` 에만 걸려서 템플릿 블록에는 효과가 없다. 프롬프트도 안내하지 않는다 | `Variant.java` |

## 규칙

- 변형(`.v-*`)은 `[data-block="…"]...:not(.ev-block)` 로 건다 — 템플릿 블록에는 걸리지 않게
- JS 가 필요한 모양은 넣지 않는다 — 생성 결과에는 script 가 없다
- 움직이는 모양(흐르는 띠 · 빛나는 버튼)은 `99-a11y` 에서 멈춘 상태를 같이 정한다
- 분리할 때(2026-10-01) 옛 단일 파일과 **규칙 498개가 같고**, 순서만 두 군데(팔레트 · reduced-motion 을 맨 뒤로) 바뀌었다.
  템플릿 5종 · 변형 조합 11종 × 720/375px 에서 계산된 스타일 차이 0 을 확인했다.
  변형 추가(같은 날) 뒤에도 기존 변형 · 템플릿은 차이 0 이다
